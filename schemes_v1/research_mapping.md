# Mapping: Academic Method to Tech-Agentic Research

Para aplicar el método de Alejandro Medina Sandín a tu proyecto de **GuruSup** y **Autoresearch**, hemos pivotado los prompts académicos hacia una "Ingeniería de Investigación Técnica".

## 1. De Tesis a "Specs" Técnicas
| Prompt Original | Adaptación Tech-Agentic | Objetivo en GuruSup |
| :--- | :--- | :--- |
| **1. Diagnóstico de Estilo** | **Code & Logic Diagnostic** | Revisar la claridad de la lógica de un agente o la documentación de su arquitectura. |
| **2. Análisis de Lit (Gaps)** | **State-of-the-Art Analysis** | Analizar repositorios de GitHub o Papers de IA para encontrar funciones que la competencia (o GuruSup) aún no tiene. |
| **3. Marco Teórico** | **Architecture Design Patterns** | Definir por qué usamos PydanticAI frente a LangGraph basándose en "principios de diseño". |
| **4. Referí Implacable** | **Senior AI Architect Review** | Simular una revisión de diseño técnica de nivel senior antes de implementar. |
| **5. Lluvia de Ideas** | **Feature Ideation (POCs)** | Generar ideas para el "AI Night Lab" que aporten valor real al negocio. |
| **6. Criba Rápida** | **Repo/Paper Triage** | Decidir si un repositorio nuevo merece ser integrado o es puro "hype". |
| **7. Extracción Profunda** | **Pattern Extraction** | Sacar el esqueleto lógico de un paper (ej: "Optimizing Tool Use") para implementarlo en `train.py`. |
| **8. Abstract (Resumen)** | **Executive Briefing** | Resumir el valor técnico de un cambio para presentarlo a Víctor o Bruno. |
| **9. Coach de Productividad** | **Sprint/Roadmap Planner** | Planificar el ciclo de experimentos de `autoresearch`. |
